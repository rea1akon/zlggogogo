## 1. 登录 Cloudflare（在 cloudflare/ 目录下执行）

```bash
cd cloudflare
npx wrangler login
```

- 会**自动弹浏览器**让你点"Allow"授权
- 授权完切回终端，会打印 `Successfully logged in`
- 授权文件保存在 `%USERPROFILE%\.wrangler\config\default.toml`（或 Home 目录 `.config/.wrangler/`）

### 登录失败的常见情况

| 现象 | 解决 |
|---|---|
| 浏览器没弹 | 看终端给的 `https://...` 链接，复制到浏览器打开 |
| 报错 `Cannot read properties of undefined` | 网络层拦截，换个时段或检查代理 |
| 想无浏览器登录 | 见附录 A：用 API Token 替代浏览器登录 |

## 2. 创建远程 D1 数据库 + 拿 ID

```bash
npm run db:create
```

- wrangler 会输出 `database_id`（形如 `a1b2c3d4-e5f6-...`）和 `uploaded_at`
- **该命令会自动改写 `wrangler.toml` 里的两处占位符**（如果脚本已写好）

如需手动复制，把 `database_id` 也**单独存到记事本**，下面要粘进去：

```bash
# 找到 wrangler.toml 里的两处占位符，全部替换为真实 ID
database_id = "00000000-0000-0000-0000-000000000000"   ←  改成上面的 ID
```

## 4. 部署 Worker 后端

### 4.1 在第一次部署前，确认 `wrangler.toml` 的 `[env.production]` 段写好了

打开 `wrangler.toml`，把第 4 节"环境变量"段里的 `ALLOWED_ORIGINS` 改成你的 Pages 域名占位（先把名字写好，下面拿到真实域名后**再回来改一次**）：

```toml
[env.production.vars]
ALLOWED_ORIGINS = "https://zlg-maintenance.pages.dev"   # 占位，第 5 步拿到真域名后回头改
```

### 4.2 一键部署到生产环境

```bash
npm run deploy:worker -- --env production
```

- 部署成功会返回：`Published zlg-maintenance-api (<秒数> seconds)`
- **Worker 域名格式**：`https://zlg-maintenance-api.<你的子域>.workers.dev`
- 把这个完整地址**存到记事本**，后面 Pages 配置要用

### 4.3 验证后端接口

```bash
BASE=https://zlg-maintenance-api.<你的子域>.workers.dev
curl $BASE/api/health                                # 期望 {"db":"connected",...}
curl -X POST $BASE/api/auth/login -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"zlg123"}'      # 期望拿到 64 位 token
```

> 第 6 节必须改默认口令（admin/zlg123），否则 CORS 安全等于零。

## 5. 部署 Pages 前端

走网页（Cloudflare 控制台）：

1. https://dash.cloudflare.com → 左侧 **Workers & Pages** → **Create** → **Pages** 标签
2. **Connect to Git** → 选 GitHub → 授权账号 → 选仓库 `rea1akon/zlggogogo`
3. **Project name** 填：`zlg-maintenance`（决定你的 Pages 域名 `zlg-maintenance.pages.dev`）
4. **Build settings（关键三处）**：

   | 项 | 填 |
   |---|---|
   | **Framework preset** | 选 `Vite`（或 `None`，下面配置覆盖） |
   | **Root directory** | 点 "Edit" → 输入 `cloudflare` |
   | **Build command** | `npm run build` |
   | **Build output directory** | `frontend/dist` |
   | **Environment variables** | 点 "Add" 加两行（见下） |

5. **环境变量**（必须加，不然后端调用会 404）：

   | Variable name | Value |
   |---|---|
   | `VITE_API_BASE` | `https://zlg-maintenance-api.<你的子域>.workers.dev/api` ← 必须是 `/api` 结尾 |
   | `NODE_VERSION` | `20` |

6. 点 **Save and Deploy**。首次构建 1~3 分钟。

### 构建成功后回头修 CORS

你会拿到正式 Pages 域名（如 `zlg-maintenance.pages.dev` 或自定义）。

回去改 `wrangler.toml` 的 `[env.production.vars.ALLOWED_ORIGINS]`：
```toml
ALLOWED_ORIGINS = "https://zlg-maintenance.pages.dev,<你的真域名>"
```
然后重新部署一次 Worker：
```bash
npm run deploy:worker -- --env production
```

## 6. 上线后必做：修改默认口令

种子账户 `admin / zlg123` 是本地用的，**任何人能登上去**，必须改。

```bash
cd cloudflare
npm run hash-password -- "你的强密码"
```

会输出 `salt` 和 `password_hash`，粘到在线 D1：

```bash
npx wrangler d1 execute zlg_maintenance_db --remote --command \
  "UPDATE users SET salt='<上面的salt>', password_hash='<上面的hash>' WHERE username='admin'"
```

完成后用旧口令登录会失败，证明改密成功。

## 8. 故障速查表

| 现象 | 排查 |
|---|---|
| Pages 构建失败 `Cannot find module 'vite'` | 环境变量漏了 `NODE_VERSION=20` |
| Pages 打开但所有接口 404 | `VITE_API_BASE` 没填或漏了 `/api` 结尾 |
| 浏览器报 CORS 报错 | `ALLOWED_ORIGINS` 没把 Pages 域名加进去，重部署 Worker |
| Worker 部署报 `database_id is invalid` | `wrangler.toml` 两处还是占位 ID，改成 `db:create` 返回的真 ID |
| 远程 D1 表不存在 | 只在本地迁移了，补跑 `npm run db:migrate:remote` |
| `wrangler login` 浏览器没弹 | 看终端的链接复制到浏览器；或见附录 A 用 API Token 替代 |

## 附录 A：无浏览器环境的 wrangler 登录（API Token 方式）

适合你的机器装不了 GUI、或者 wrangler 浏览器跳转失败：

1. 浏览器登录 https://dash.cloudflare.com/profile/api-tokens
2. **Create Token** → 模板选 **Edit Cloudflare Workers**（已含 Workers + Pages 权限）
3. **Account Resources** 选 *All accounts* 或指定账号
4. **Zone Resources** 选 *All zones* 或 All zones
5. 创建 → 复制 token（只显示一次）
6. 在终端：
   ```bash
   export CLOUDFLARE_API_TOKEN=<你的token>
   npx wrangler whoami    # 能看到账号即成功
   ```
   之后所有 wrangler 命令会自动用这个 token。

## 附录 B：清理与回滚

| 想做的事 | 怎么做 |
|---|---|
| 删 Worker | 控制台 Workers & Pages → 选 Worker → Settings → Delete |
| 删 Pages 项目 | 控制台 → Pages → 选项目 → Settings → Delete |
| 删 D1 数据库 | 控制台 → D1 → 选库 → Delete（不会级联删除，需确认无引用） |
| 重置部署（不改代码） | 在 Pages → Deployments → 点某次部署 → "Rollback to this deployment" |
| 修改代码后重新部署 | 推代码到 GitHub，Pages 自动重部署；Worker 需 `npm run deploy:worker -- --env production` 手动触发 |
